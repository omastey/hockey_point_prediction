DATE: 2026-03-04
PROMPT: "Ok lets go back to the delta stats, why were they not working and how
can we truly fix them to be effective features"

ROOT CAUSE IDENTIFIED:
  - The 20202021 season has zero rows in the EDGE dataset (API has no Edge
    skating data for that season). The earliest available season is 20212022.
  - In the training set (seasons < 20232024), players have at most 20212022 and
    20222023. Since 20212022 is the first season for all players, those rows
    have NaN deltas. Only ~50% of training rows (20222023) have valid deltas.
  - Counting stat deltas (shots, pp_points, burstsOver20, totalDistance) were
    computed on raw season totals, making them confounded with gamesPlayed
    changes rather than true per-game performance changes.

CHANGES:
  src/train_xgb.py
    - Converted counting stats to per-game rates before computing deltas:
      shots_pg, pp_points_pg, bursts_pg, distance_pg
    - Delta cols now split into rate_delta_cols (toi, ppg, gpg, apg, oz_pct —
      already per-game rates) and count_delta_cols (the four new pg versions +
      gamesPlayed). Old delta_shots, delta_pp_points, delta_burstsOver20,
      delta_totalDistance removed in favour of per-game equivalents.
    - Added has_prior_season binary flag (1 if player has a prior qualifying
      season, 0 if first row) so tree models can learn to discount delta values
      that were NaN-filled rather than genuine zero-change rows
    - Added prev_season_gp (games played in prior season) as context for
      interpreting delta magnitudes

  FEATURES.md
    - Updated delta features section to reflect per-game rate deltas
    - Added Delta Context Features section documenting has_prior_season and
      prev_season_gp
